# Shared scene helpers

Cross-scene utilities. Small, pure-function modules used by two or more scenes.

## Files

- `iso-math.ts` — screen ↔ tile coordinate conversions for the 64×32 (2:1) isometric grid (legacy iso world; kept for reference).
- `y-sort.ts` — pure `calculateYSortDepth(obj, { depthBase, yAnchorRatio })` used by every image-backed scene for per-frame depth sorting.
- `avatar-palette.ts` — 8 stable `AVATAR_IDS`, `AVATAR_COLORS` (Tailwind-500 palette for Rectangle placeholders), `AVATAR_NAMES` (human-readable labels shown in the onboarding picker), `AvatarId` type + `isAvatarId` guard.
- `types.ts` — cross-scene TS types: re-exports `AvatarDirection` + `AVATAR_DIRECTIONS` (cardinal n/e/s/w) from `@arcadia/shared` so client code uses the exact literals the Colyseus protocol ships. Local types: `AvatarAction` (`idle`/`walk`/`jump`), `BUILDING_NAMES` + `BuildingName` + `isBuildingName`, `TileCoord`, `PixelRect`.
- `colliders.ts` — `spawnColliders(scene, rects)` StaticGroup builder. All image-backed scenes ship empty collider arrays and activate the moment rects are authored (Phase-5 Step 15 scaffold).
- `enter-prompt.ts` *(2026-04-22)* — proximity "Press ENTER to visit X" prompts used by the three outdoor scenes. (Originally on SPACE; moved to ENTER on 2026-04-22 so jump stops eating the prompt.) Exports `findNearestActiveTrigger` (pure, unit-tested) + `createEnterPromptManager`. **2026-04-24:** `EntryTrigger` gained optional `halfWidth` / `halfHeight` — when both set, the trigger is an axis-aligned rectangular zone instead of a circle (used by coworking-outside tents as 200×200 squares). `createEnterPromptManager` also now accepts an optional `onFire` callback for pre-navigate hooks (used by the tavern interior to send `LEAVE_BUILDING` before the camera fade). **Phase 8:** the pill visual was restyled — IM Fell English italic on 0.95-alpha night with a bronze-deep + bronze-bright double border, 4 px corners (was Georgia bold yellow on dark blue, 10 px corners).
- `proximity-prompt.ts` *(Phase 8, 2026-04-24)* — local-action variant of `enter-prompt`. Same visual pill but the ENTER handler is a caller-supplied callback instead of a route navigation. Used by the academy lectern ("open the Scribe's Ledger") + market crystal ("browse the catalog") to open React modals instead of navigating.
- `edge-triggers.ts` *(2026-04-22)* — walk-onto scene-edge portals. Exports `hitEdge` (pure) + `createEdgeTriggerManager`. Used by the square (4 edges) and each outdoor scene (1 return edge). **2026-04-23:** `EdgeTriggerConfig` gained optional `promptLabel` (ENTER-gated edges, used by the square's 4 exits + market / coworking-inside / academy-interior returns) and optional `span: { min, max }` (narrow-gate confinement, used by the square's east-Tavern edge + market's top archway).
- `capacity-hud.ts` *(2026-04-22)* — top-right fade-in pill showing `<label> · <count> / <max>`. Used by `SquareScene`, `TavernScene`, `CoworkingInsideScene` — one per Colyseus-backed scene. Driven by `room.state.avatars.size` on each add/remove callback.
- `outdoor-scene-base.ts` *(2026-04-22)* — abstract Phaser scene the three outdoor scenes extend (`AcademyOutsideScene`, `TavernOutsideScene`, `CoworkingOutsideScene`). Owns image load, LocalAvatar wiring, input loop, SPACE-is-jump, and ENTER-is-enter-prompt. Subclasses only declare scene key + `sceneConfig` (assembled from sibling `*.config.ts` files per ADR 0004). Also reads `OUTDOOR_SPAWN_OVERRIDE_REGISTRY_KEY` so `/tavern-outside` can spawn the member next to a specific tavern door when returning from an interior.
- `overlay-input-events.ts` *(2026-04-25)* — bridge for "an overlay input field has focus → release Phaser's keyboard captures so the user can type WASD / SPACE / ENTER". Phaser's KeyboardManager attaches at *capture phase* on `window`, so a textarea calling `event.stopPropagation()` doesn't help — the only reliable fix is to disable the keyboard plugin while the overlay is open. React overlays call `emitOverlayInputFocus()` / `emitOverlayInputBlur()` (custom DOM events on `window`); Phaser scenes call `bindOverlayInputBridge(scene, { capturesOnBlur })` once in `create()` and the returned teardown in `shutdown()`. Used by `SquareScene` + `TavernScene`; emitted by `SageDialogue` + `FeedScroll`. Decoupled from each scene's chat-specific events, so any future overlay can plug in without per-scene wiring.
- `building-names.ts` *(2026-04-22)* — display-name maps for per-building Colyseus shards. `TAVERN_DISPLAY_NAMES` (`tavern-a` → "The Three Ravens", etc.) + `tavernDisplayName()` / `tentDisplayName()` helpers feed the HUD + transition overlay labels.
- `npc-swarm.ts` *(2026-05-06 · PR #62)* — demo NPCs that wander every Phaser scene when simulation mode is on. Reuses `avatar-renderer` + `avatar-animations` so each NPC visually reads identical to a real remote peer. State machine per NPC: walking → arrive (within 6 px) → idle 1–4 s → pick new target → repeat. Random per-NPC level (1–12) + random ambient speech bubbles every 5–14 s (5 s lifetime). 8-persona pool alternating avatar-01 + avatar-02 with placeholder names. Reads `isSimulationOnClient()` on construct + listens for `SIM_CHANGE_EVENT` on window — flipping the toggle spawns or despawns the swarm immediately. Wired into the 5 interior/multiplayer scenes + the outdoor base; ~36 NPCs across the world when sim is on.
- `speech-bubble.ts` *(2026-05-06 · PR #62 — extracted from TavernScene)* — `createSpeechBubble(scene, text)` factory + `SPEECH_BUBBLE_DEPTH` / `SPEECH_BUBBLE_DURATION_MS` / `SPEECH_BUBBLE_Y_OFFSET` constants. Dark rounded-rect with vellum Georgia text + downward tail; container origin at bottom-centre so callers position it via `setPosition(speakerX, speakerY - SPEECH_BUBBLE_Y_OFFSET)`. Used by both `TavernScene` (player chat bubbles) and `NpcSwarm` (random ambient mutterings) so the visuals never drift.

## Configs

None. Shared helpers have no config files — if a value is shared between scenes, it lives here as an exported `const`, not in a per-scene config.

## Config leak discipline

If a value is used by only one scene, it belongs in that scene's `sprites.config.ts` / `camera.config.ts` / `layers.config.ts` — **not** here. Pulling a scene-local value into `shared/` is premature sharing. Wait until a second scene actually needs it.
