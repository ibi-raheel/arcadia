# 2026-04-20 — Phase 3 exit: Academy is live

Creator → member content loop works end-to-end on prod. A creator builds a course with a video + written lesson, publishes, and a member finds it at `/academy`, watches the video (progress tracked + resumed across refresh), reads the written lesson (scroll-to-90% marks it done), and watches the course progress bar fill.

## What shipped in Phase 3

### Creator side (Week 9)

- **`/dashboard`** — role-gated (`memberships.role in ('creator','admin')`). Course list, "Create course" dialog, publish/draft toggle.
- **`/dashboard/courses/[id]`** — two-pane editor. Left rail: sections + lessons with drag-reorder (`@dnd-kit/sortable`) + inline rename + delete-with-confirm (cascade-deletes lessons on section delete). Right pane: Markdown editor (`@uiw/react-md-editor`, 2 s debounced autosave) or YouTube URL editor based on lesson type. Type toggle both ways.
- **Role gate + hub** — home page (`/`) is a two-card hub for authed users: **Enter the World** always, **Open the Dashboard** for creators/admins only.

### Member side (Week 10 + Phase 3.5)

- **`/academy`** — **Phaser scene** (not the originally-planned React grid). Member walks the interior, clicks a course podium (shows title + completed/total/% progress) to open the course viewer.
- **`/academy/[courseId]`** — React viewer. Left rail tree + header progress + YouTube IFrame Player for video lessons (resumes at `watched_secs` with end-clamp) + `react-markdown` renderer for written lessons with 90%-scroll completion via IntersectionObserver.

### Video host

**YouTube unlisted**, demo-only per ADR 0006. Zero credentials, zero quota, zero new account. Swap-back path to a real host (CF Stream / Cloudinary / Mux) documented in the ADR and required before any paying creator uploads.

### Schema

Four migrations applied to both `arcadia-test` and `arcadia` prod:

1. `20260421000001_phase3_courses_lessons_progress` — `courses.creator_id`, `lessons.youtube_video_id`, `lessons.duration_sec`, creator-scoped RLS for courses/sections/lessons, enrolment insert policies.
2. `20260421000002_phase3_storage_course_thumbnails` — Supabase Storage bucket `course-thumbnails` (public-read, 2 MB cap, jpeg/png/webp allowlist, owner-scoped write).
3. `20260421000003_phase3_membership_roles` — `memberships.role` + `user_has_creator_role()` helper; course INSERT wraps the helper.
4. `20260421000004_phase3_set_lesson_duration` — SECURITY DEFINER RPC so the viewer can populate `duration_sec` on first play (creator-only UPDATE policy kept; RPC is the sanctioned viewer-side writer).

## Same-day scope amendments

Two meaningful deviations from the Phase 3 plan, both user-initiated:

1. **Decision A revised.** Any-authed-member-can-create → creator role required. Migration + role-aware UI shipped same session.
2. **Decision D/G/K/M pivoted twice.** CF Stream → Cloudinary → YouTube unlisted. Second pivot landed an explicit demo-only scope and hard exit criteria in ADR 0006.

One scope **addition** on top of the plan:

3. **Phase 3.5 — Phaser Academy.** The plan (and TAD §4.2) said "Academy never gets a Phaser scene". User wanted a walk-around hall like the Tavern. Built same-day; user-supplied 1536×1024 interior; podiums arranged by DB row; click → React course viewer. Superseded TAD §4.2 inline; promote to an ADR before Phase 5 if it sticks.
