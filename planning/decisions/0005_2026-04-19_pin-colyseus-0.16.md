# ADR 0005: Pin Colyseus ecosystem to 0.16.x (server + client matched)

- **Status:** Accepted
- **Date:** 2026-04-19
- **Deciders:** Arcadia build owner
- **Amends:** ADR 0001 §Multiplayer — supersedes the "Colyseus 0.17+" selection for the MVP.

## Context

Phase 2 Week 7 shipped the first real Colyseus wiring (remote avatars, state subscription, matchmake + onAuth). On the first deployed run the client threw:

```
undefined is not an object (evaluating 'e.room.name')
    at consumeSeatReservation (colyseus.js/build/esm/Client.mjs:106)
```

and the server subsequently crashed on the first state broadcast with:

```
TypeError: Cannot read properties of undefined (reading 'Symbol(Symbol.metadata)')
    at encodeValue (@colyseus/schema/build/cjs/index.js:1481)
```

Root causes (found via runtime logs, per the existing memory rule):

1. **Seat-reservation shape changed between server 0.16 and 0.17.** `buildSeatReservation` in `@colyseus/core@0.17` returns a flat object `{ name, sessionId, roomId, processId }`; `colyseus.js` client 0.16.22 (the latest published) reads `response.room.name` — nested. `colyseus.js@0.17` is not published on npm, so the server must drop back to match the client.

2. **`@colyseus/schema@3` expects field initialisers compiled as plain constructor assignments.** Root `tsconfig.base.json` had `useDefineForClassFields: true`, which turns `@type(...) avatars = new MapSchema()` into `Object.defineProperty` on each instance. That shadows the prototype-level legacy decorator at runtime → `$childType` never lands on the MapSchema → encoder dereferences `undefined` on the first broadcast.

3. **`uWebSockets.js` peer dep on `@colyseus/uwebsockets-transport` is GitHub-only** (the package name has capital letters, blocked by the npm registry for new registrations). npm normalises the `github:user/repo` shorthand to `git+ssh://…` which Railway's build container can't resolve (no SSH key).

## Decision

Pin the Colyseus server ecosystem to `^0.16.0` so it matches the client the npm registry actually ships:

- `colyseus` → `^0.16.0` (resolves to `0.16.5`)
- `@colyseus/ws-transport` → `^0.16.0` (`0.16.5`)
- `@colyseus/redis-driver` → `^0.16.0` (`0.16.1`)
- `@colyseus/redis-presence` → `^0.16.0` (`0.16.4`)
- `@colyseus/monitor` → `^0.16.0` (`0.16.7`)
- `@arcadia/shared` → `@colyseus/schema@^3.0.0` (single hoisted copy; same major as server + client resolve to)
- `colyseus.js` (client) → `^0.16.0` (already this — `0.16.22`)

Revisit once colyseus.js 0.17 is released on npm (currently no stable / preview / next tag past 0.16.22 as of 2026-04-19).

## Consequences

### Code deltas required by the 0.16 API

- `Room<State>` generic is `Room<RealmRoomState>` — direct, not wrapped in `{ state: State }` like 0.17.
- `onLeave(client, consented?: boolean)` instead of 0.17's `onLeave(client, code?: number)`.
- `state.avatars.onAdd/onRemove/onChange` access via `getStateCallbacks(room)` proxy (unchanged across 0.16 / 0.17 client).

### Build-config workarounds

Both are recorded alongside their fix in `phases/phase-02_status.md` and summarised here for discoverability:

- **`packages/shared/tsconfig.json`** must override `useDefineForClassFields: false`. Without it, the MapSchema decorator breaks and the room disposes on first patch.
- **Root `package.json`** carries an override for `uWebSockets.js`:
  ```json
  "overrides": {
    "uWebSockets.js": "git+https://github.com/uNetworking/uWebSockets.js.git#v20.49.0"
  }
  ```
  And `package-lock.json`'s `resolved` URL for that package must be HTTPS (`git+https://`). `npm install` locally re-writes it to `git+ssh://` — `npm ci` (which Railway uses) preserves the lockfile as-is, so committing the HTTPS form is enough. If a local `npm install` rewrites it, re-run:
  ```sh
  sed -i '' 's|git+ssh://git@github.com/uNetworking/uWebSockets.js.git|git+https://github.com/uNetworking/uWebSockets.js.git|g' package-lock.json
  ```

## Rejected alternatives

- **Ship server 0.17 + patch colyseus.js locally** — fragile. Would break on every client-package update. The seat-reservation shape is load-bearing; patching changes the wire protocol.
- **Upgrade shared to `@colyseus/schema@4`** — no 0.17-compatible server to pair it with yet (0.17 server also uses schema 3, per its peer deps). Would make the issue worse.
- **Switch to Socket.io / custom WS transport** — rejected in ADR 0001. Still rejected — we would lose state-schema diff syncing + room lifecycle.

## Revisit trigger

When **colyseus.js@0.17** is published on npm (stable or next tag), evaluate upgrading both sides back to 0.17. Open a new ADR that supersedes this one.
